Encryption Type Matcher
Six real-world scenarios involving cryptography. Identify whether each uses symmetric encryption, asymmetric encryption, or hashing — then answer the follow-up question about why that type was chosen.
SYMMETRIC
Same key encrypts and decrypts. Fast. Key must be shared securely.
AES-256, AES-128, 3DES
ASYMMETRIC
Public key encrypts, private key decrypts. Slow. No shared secret needed.
RSA, ECC, Diffie-Hellman
HASHING
One-way. No decryption. Fixed-length output. Verifies integrity.
SHA-256, SHA-3, bcrypt, MD5
// KEY CONCEPTS
SYMMETRIC vs ASYMMETRIC
Symmetric (AES) is fast — used for bulk data encryption. Asymmetric (RSA) is slow but solves the key distribution problem. TLS uses both: asymmetric to establish a shared secret, then symmetric for the actual data transfer.
HASHING IS NOT ENCRYPTION
Hashing is one-way — you cannot "decrypt" a hash. Encryption is reversible with a key. Hashing verifies integrity (passwords, file integrity) while encryption protects confidentiality. The AP exam tests this distinction directly.
PASSWORD STORAGE
Passwords should NEVER be stored as plaintext or reversibly encrypted. They're stored as salted hashes (bcrypt, Argon2). At login, the entered password is hashed and compared to the stored hash. The original password is never recoverable.
DIGITAL SIGNATURES
A digital signature uses asymmetric cryptography: the sender signs with their private key, recipients verify with the public key. This proves authenticity (who sent it) and integrity (wasn't modified). Used in code signing, email (S/MIME), and TLS certificates.
